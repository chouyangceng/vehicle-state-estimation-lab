# RL 自适应传感器选择研究设计

**日期：** 2026-07-30
**项目：** `vehicle-state-estimation-lab`
**状态：** 已获用户方向确认，待规格复核

## 1. 研究目标

在已有车辆工况生成、传感器消融、经验可观测 Gramian、CRLB 和 ROS 2 接口基础上，增加一个轻量、可解释、可复现的强化学习研究模块。智能体在车辆运行过程中动态选择 IMU、轮速和 GNSS 的非空组合，在状态不确定度、不可观测风险、传感器能耗/通信成本以及频繁切换代价之间取得平衡。

本阶段回答的核心问题是：**相较于始终开启全部传感器、固定低成本配置、随机选择和单步贪心选择，时序 RL 策略能否在近似保持可观测性与估计精度的同时降低传感器使用成本？**

研究结论只适用于当前透明的车辆与传感器仿真。报告必须明确：协方差与 CRLB 是局部线性化下的不确定度代理，不能替代实车道路试验。

## 2. 方案选择

采用仅依赖 NumPy 的表格型 Q-learning，不引入 PyTorch、Gymnasium 或 GPU 依赖。

选择理由：

- 离散状态和动作能直接画出策略表，便于科研答辩解释；
- 固定随机种子后训练结果可复现；
- 训练时间短，普通本科生电脑即可运行；
- 导出的策略表能脱离训练器执行，适合接入 ROS 2；
- 可与上下文老虎机和单步贪心基线清楚区分，体现长期回报与切换代价。

DQN 不在本阶段实现。只有当连续状态实验表明离散化成为主要性能瓶颈时，才将其作为后续研究扩展。

## 3. 系统边界与架构

系统分成五个互相独立的单元：

1. `SensorSelectionEnv`：将确定性车辆轨迹、传感器线性化模型、协方差传播和成本模型封装为 `reset()` / `step()` 接口。
2. `StateDiscretizer`：把连续车辆速度、激励程度、不确定度、传感器健康状态和上一动作转换成有限状态编号。
3. `QLearningAgent`：完成带种子的 epsilon-greedy 训练、Q 表更新、确定性推理和策略导出。
4. 基线与评估器：使用同一环境评估 `always_all`、`lowest_cost`、`random`、`greedy_information` 与 RL 策略。
5. CLI 与 ROS 2 推理适配器：CLI 负责训练、评估和生成报告；ROS 2 只加载已训练策略并发布传感器启用位掩码，不在车端在线训练。

核心算法保持 ROS 2 无关；未安装 `rclpy` 时全部训练、测试和离线实验仍可运行。

## 4. 环境定义

### 4.1 时间与轨迹

一个 episode 使用现有四类工况之一：直线、正弦转向、双移线和低附着切换。轨迹按固定窗口划分，每一步对一个窗口作传感器选择。训练 episode 按种子确定的顺序覆盖全部工况，避免只对某一工况过拟合。

### 4.2 动作空间

动作是以下七个非空传感器组合，顺序固定并写入策略文件：

1. IMU
2. 轮速
3. GNSS
4. IMU + 轮速
5. IMU + GNSS
6. 轮速 + GNSS
7. IMU + 轮速 + GNSS

传感器发生故障时，包含故障传感器的动作视为不可用。环境对不可用动作给出明确惩罚，并确定性地回退到“全部健康传感器”动作继续 episode。若健康位掩码为零，则该 episode 以安全失败状态终止，不伪造可用观测。

### 4.3 状态空间

离散状态由五部分组成：

- 速度档：窗口平均速度按 `[2, 15] m/s` 分为低、中、高；
- 横向激励档：窗口平均绝对横摆率按 `[0.02, 0.12] rad/s` 分为低、中、高；
- 不确定度档：将协方差对数迹相对配置的危险上限归一化到 `[0, 1]`，再按 `[0.25, 0.50, 0.80]` 分为低、中、高、危险；
- 传感器健康位掩码：IMU、轮速、GNSS 三位；
- 上一动作编号：七个动作加初始空动作。

所有分箱边界写入配置和策略 JSON，推理阶段不得隐式改变。默认状态总数为 `3 × 3 × 4 × 8 × 8 = 2304`，Q 表包含 `2304 × 7 = 16128` 个数值，普通 CPU 与内存足以完成训练和部署。

### 4.4 不确定度转移

每步先用可配置过程噪声使先验协方差增长，再使用当前窗口内所选传感器的线性化信息矩阵更新后验：

\[
P^-_t = P_{t-1} + Q\Delta t,\qquad
\Lambda_t = (P^-_t)^{-1} + \sum_{s\in a_t} H_{s,t}^{\mathsf T}R_s^{-1}H_{s,t},\qquad
P_t = \operatorname{bounded\_inverse}(\Lambda_t).
\]

`bounded_inverse` 在可观测特征方向使用特征值倒数，在零空间方向使用配置的危险方差上限，仅作为有限的训练代理。实现同时保留未经填充的有效秩和零空间掩码；若信息矩阵秩不足，该步必须标记为不可观测，不能因为代理协方差有限就误报为真实可观测。矩阵运算还使用对称化和有限值检查保持数值稳定。

### 4.5 成本与奖励

默认相对成本为轮速 `1.0`、IMU `2.0`、GNSS `5.0`，组合成本为各传感器成本之和，并允许在配置中修改。单步奖励为：

\[
r_t = -w_u\,U(P_t) - w_c\,C(a_t) - w_s\,\mathbf{1}[a_t\ne a_{t-1}]
      + w_i\,G_t - w_o\,\mathbf{1}[\operatorname{rank}(\Lambda_t)<n],
\]

其中 `U` 是归一化不确定度，`C` 是传感器成本，`G` 是相对上一步的信息增益。各项先归一化再加权，CLI 报告每个奖励分量，防止只展示总回报而无法解释策略行为。

## 5. Q-learning

使用标准更新：

\[
Q(s_t,a_t)\leftarrow Q(s_t,a_t)+\alpha
\left[r_t+\gamma\max_a Q(s_{t+1},a)-Q(s_t,a_t)\right].
\]

训练采用线性 epsilon 衰减和显式随机种子。训练集依次覆盖全健康、GNSS 暂时失效、IMU 暂时失效和轮速暂时失效四类健康配置；失效窗口由独立的带种子随机数生成器生成，并保证至少一个传感器健康。相同配置、相同种子必须产生字节级一致的策略 JSON 和数值一致的评估结果。并列动作按固定动作顺序选择，避免平台差异造成非确定性。

策略 JSON 包含格式版本、状态分箱、动作表、Q 表、训练超参数、成本模型、种子和训练摘要。加载器拒绝未知版本、非有限 Q 值、形状错误和动作定义不一致。

## 6. 基线与评价协议

所有策略使用完全相同的工况、故障调度和随机种子评估。至少报告：

- 平均与 P95 后验不确定度；
- 累计回报及各奖励分量；
- 归一化传感器成本和相对 `always_all` 的节省比例；
- 各传感器占空比、动作切换次数；
- 不可观测步数和比例；
- 各工况单独结果与汇总结果。

RL 只有同时满足以下条件才可在报告中描述为“优于固定全传感器基线”：成本降低，且平均不确定度和不可观测率没有超过配置中的容许退化阈值。否则报告必须使用“不同权衡”，不能作优越性结论。

## 7. 命令行与输出

新增入口：

```bash
python experiments/rl_sensor_selection.py \
  --config configs/rl_sensor_selection.yaml \
  --seed 7 \
  --output artifacts/rl-sensor-selection
```

`--fast` 使用较少 episode，供 CI 和快速演示；默认模式用于正式实验。输出包括：

- `policy.json`：可部署的策略与元数据；
- `training_history.csv`：逐 episode 回报、成本和不确定度；
- `evaluation.json`：严格 JSON 的完整评估结果；
- `policy_comparison.csv`：RL 与四个基线的对比；
- `training_curve.png`：训练回报与移动平均；
- `tradeoff.png`：成本—不确定度散点图；
- `action_usage.png`：不同工况动作占比；
- `summary.md`：中文实验结论、奖励定义、假设和局限。

所有输出使用无图形界面的 Matplotlib `Agg` 后端。JSON 禁止 `NaN` 和 `Infinity`。

## 8. ROS 2 推理接口

新增可选策略节点，加载 `policy.json`，从 `nav_msgs/Odometry` 的速度和协方差、`diagnostic_msgs/DiagnosticArray` 的传感器健康状态构造离散状态，并发布 `std_msgs/UInt8` 传感器位掩码：位 0 为 IMU、位 1 为轮速、位 2 为 GNSS。

节点只做确定性推理，并提供以下安全机制：

- 策略或输入无效时回退到全部健康传感器；
- 没有健康传感器时发布零位掩码并输出 ERROR 诊断；
- 输入超时或协方差不可用时不使用低成本激进动作；
- 发布当前状态编号、动作、推理原因和回退标志作为诊断信息。

## 10. 错误处理与可复现性

- 配置拒绝未知键、空动作表、非有限权重、负成本、非法概率和不单调分箱；
- 环境拒绝形状错误、时间戳不一致和含非有限值的轨迹；
- 不允许智能体选择空传感器组合；
- 训练和评估使用分离的随机数生成器，避免评估改变训练轨迹；
- 输出写入新目录；已有非空目录默认拒绝覆盖，除非显式指定 `--overwrite`；
- 配置、种子、Git 提交号和软件版本写入评估元数据。

## 11. 测试与验收标准

全部生产代码采用测试先行。最低验收标准如下：

1. 环境转移、奖励分解、故障动作回退和终止条件有确定性单元测试；
2. 分箱边界、策略并列选择、Q 更新公式和 epsilon 衰减有数值测试；
3. 同一随机种子训练两次，Q 表、策略文件和汇总指标一致；
4. 不同种子允许产生不同探索轨迹；
5. 策略序列化可往返，损坏或不兼容策略被明确拒绝；
6. 四个基线与 RL 使用同一评估 episode；
7. `--fast` 在普通 CPU 上快速完成并生成所有约定文件；
8. ROS 2 纯 Python 桥接测试不依赖安装 ROS 2；
9. 完整 pytest、Ruff、compileall 和 GitHub Actions 均通过；
10. 文档给出可运行命令、指标解释、科研结论边界和后续实车验证路线。

## 12. 非目标

本阶段不实现端到端自动驾驶、不让 RL 直接控制转向或制动、不在线更新车端策略、不声称达到量产功能安全要求，也不使用未经标定的仿真数字冒充真实节能比例。
