# 可解释 RL 自适应传感器选择

这个实验研究车辆状态估计中的一个具体问题：IMU、轮速和 GNSS 不必在每个时刻全部开启时，如何在不确定度、瞬时可观测性、传感器成本与切换频率之间作透明的时序权衡。

## 一键复现

```bash
python experiments/rl_sensor_selection.py --fast --seed 7
```

去掉 `--fast` 会使用 320 个训练 episode、48 个独立评估 episode 和更长的决策轨迹。输出默认位于 `artifacts/rl-sensor-selection/`：

- `policy.json`：版本化 Q 表、动作定义、分箱和实验元数据；
- `training_history.csv`：逐 episode 回报、不确定度、成本和故障回退次数；
- `evaluation.json`：学习策略与四个基线的严格 JSON 指标；
- `policy_comparison.csv`：适合表格软件分析的策略对照；
- `training_curve.png`：回报、协方差代理和成本的训练过程；
- `tradeoff.png`：成本—不确定度前沿；
- `action_usage.png`：七种传感器组合的占比；
- `summary.md`：带预先声明判断条件的中文结论。

输出目录非空时程序默认拒绝覆盖。只有明确传入 `--overwrite` 才会更新已有产物。

## 闭环结构

每个 episode 循环覆盖直线、正弦转向、双移线和低附着切换四类确定性工况。环境把轨迹划分为决策窗口，状态由速度、横向激励、归一化协方差迹、三位传感器健康掩码和上一动作组成，共 2304 个离散状态。

动作顺序固定为：

| 编号 | 组合 | 位掩码 |
|---:|---|---:|
| 0 | IMU | 1 |
| 1 | 轮速 | 2 |
| 2 | GNSS | 4 |
| 3 | IMU + 轮速 | 3 |
| 4 | IMU + GNSS | 5 |
| 5 | 轮速 + GNSS | 6 |
| 6 | 全部 | 7 |

动作包含失效传感器时，环境施加可见的无效动作惩罚，并确定性回退到全部健康传感器。健康掩码为零时 episode 安全终止，不虚构观测。

## 协方差与可观测性

环境先传播过程噪声，再叠加所选传感器的信息矩阵：

\[
P^- = P + Q,\qquad
J = \sum_{s\in a}J_s,\qquad
P^+ = \left((P^-)^{-1}+J\right)^{-1}.
\]

数值逆使用有限危险方差作边界，只用于训练代理。当前动作是否可观测始终由纯传感器矩阵 `J` 的秩判断，而不是由包含满秩先验的后验精度判断。这一区分避免“协方差有限”被误读为“当前传感器组合能够观测全部状态”。

奖励由六个逐步记录的分量组成：不确定度、传感器成本、切换成本、信息增益、不可观测惩罚和无效动作惩罚。报告保留各分量之和，便于解释策略为何选择某个动作。

## 公平对照

同一组工况和故障调度用于：

1. Q-learning；
2. 始终请求全部传感器；
3. 固定最低成本轮速；
4. 带种子的均匀随机策略；
5. 当前窗口信息量贪心策略。

只有当 Q-learning 同时降低成本，并把平均不确定度退化控制在 10% 内、不可观测率退化控制在 5 个百分点内，报告才会描述为优于全传感器基线；否则只描述为不同权衡。

## 测试与科研边界

环境转移、纯信息秩、故障回退、安全终止、奖励守恒、种子复现、策略 JSON 往返、五策略统一评估和全部图表产物均有自动化测试。

这些数字来自低阶车辆模型和人为透明的信息矩阵，不是实车节能率、定位安全证明或功能安全认证。下一阶段应使用同步的 CAN、IMU、轮速和 GNSS 数据重新标定噪声与成本，并通过硬件在环和封闭道路实验检验策略。
